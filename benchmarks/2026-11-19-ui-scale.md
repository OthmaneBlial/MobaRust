## Session tree at scale

Generated with the preview-only `?previewScale=N` parameter, which adds N SSH sessions spread over 8 regions × 40 racks. Each value is one run.

| Sessions | Change | First paint | Search "host-12" | Clear search | Tab click | Heap |
|---|---|---|---|---|---|---|
| 2,000 | before | 500 ms | 59 ms | 328 ms | 108 ms | 77 MB |
| 2,000 | after | 268 ms | 51 ms | 150 ms | 4 ms | 49 MB |
| 5,000 | before | 952 ms | 121 ms | 880 ms | 284 ms | 80 MB |
| 5,000 | after | 520 ms | 90 ms | 363 ms | 6 ms | 100 MB |

**Fix:** the filtered list and the session tree are memoized, and row actions go through a ref. Per-folder SSH counts are computed in one pass instead of folders × sessions. Folder groups use `content-visibility: auto`.

**Still open:**
- Clearing a search at 5,000 sessions still renders every row (363 ms). Virtualizing the list would fix it if real imports get that large.
- Heap numbers from single runs are noisy.

## Synthetic Rust harness (`cargo xtask benchmark`, same day)

- Terminal batching: 18.7–24.5 GiB/s on the mixed, long-Unicode and progress-redraw fixtures. This matches the 2026-10-02 receipt.
- Session search over 10,000 profiles: 0.65 ms median.
- Raw output was not committed, following `benchmarks/README.md`.

## Not measured here

- xterm rendering throughput of large output.

These need the native app, which is deferred to the end of the 2.0 work.
