02 / move

Files belong beside the shell.

SFTP and SCP operations use bounded, cancellable pipelines. Remote editing is designed around a temporary local representation, conflict detection where possible, an atomic upload path, and preservation of the original permission bits.

The useful details

  • Recursive transfers report progress without spawning uncontrolled work.
  • Remote filenames are treated as untrusted input and normalized before local use.
  • Failed uploads remain visible instead of becoming silent partial writes.
  • Remote edits warn before overwriting a file changed since it was opened.

03 / operate

Context is an operator feature.

Saved sessions, groups, tags, snippets, tunnels, diagnostics, monitoring, and visible transfer state are designed as one operating surface. The goal is fewer hidden states, not more panels.

Broadcast input is explicit: the user selects target terminals, the UI shows a highly visible active indicator, and an emergency disable path remains available. Snippets are previewed before sending and never execute automatically. SSH monitoring is one-shot by default; live refresh requires an explicit 15/30/60-second choice and stops when the view closes.

Built to stay responsive

Search and storage are structured for large session collections. Every network operation has an operation-specific timeout and a cooperative cancellation path. Native RDP/VNC helper-pipe writes and VNC protocol input/refresh writes also have dedicated deadlines; a native Stop signal can cancel an in-flight VNC input or framebuffer-refresh operation before the bounded close path; remote-desktop helpers require a typed Hello → Starting → Ready sequence before capabilities or active data are accepted, and reconnecting is allowed only after a ready cycle; reconnecting also clears cached capabilities, remote clipboard text, the displayed framebuffer, pressed keys, and queued pointer motion before a new attempt; VNC event polling yields every 250 ms so Stop remains responsive during quiet sessions; connection metadata is bounded and rejects control characters and accidental leading/trailing whitespace before a listener, helper, or protocol channel is opened; diagnostics read native command output through a 64 KiB cap before buffering and apply a second line/count bound before IPC; RDP viewport resize requests are coalesced to the latest bounded size and cancelled when the view closes; RDP pointer and wheel coordinates are clamped to the negotiated surface before native input events are created; VNC pointer and wheel coordinates are clamped to the active framebuffer after server resize; framebuffer dimensions are bounded before launch or resize; RDP color depth is validated against the candidate's supported 16/32-bit contract; unsupported RDP audio is rejected before launch; RDP resize is revalidated inside the helper; closed RDP input/output channels route through a bounded, user-configurable 0–10-attempt reconnect policy and cleanup handling; one stable redacted crash diagnostic is emitted for a failure, reader exits trigger bounded helper cleanup/reaping, and reconnect uses bounded retries and backoff instead of an infinite loop.

04 / safety

Local-first does not mean careless.

The repository's validation path is deliberately defensive. It uses isolated `HOME` and XDG directories, strips credential-related environment variables, and runs protocol fixtures only on loopback addresses.

  • Personal `~/.ssh`, GitHub keys, SSH agents, Keychain, and real remote hosts are out of scope for tests.
  • Passwords, private key material, tokens, and sensitive environment variables are redacted from logs.
  • Frontend IPC is typed and narrow; there is no unrestricted `execute_anything(command)` bridge.
  • Native terminal, persistence, and vault errors do not echo local paths or raw OS/backend details.
  • Sanitized diagnostic export contains runtime metadata only; sessions, hosts, commands, paths, logs, and credentials are excluded.
  • Package smoke tests exercise only the built binary's no-window `--version` path; full GUI and cross-platform startup measurements remain separate.
  • Terminal output is untrusted content and is not promoted to arbitrary HTML.
  • Multiline terminal paste requires confirmation by default; it is never silently sent as a command.

06 / clipboard

Trust it before you bridge it.

RDP clipboard redirection is disabled by default. An explicit profile opt-in selects IronRDP’s native Windows clipboard backend; macOS and Linux reject the option until reviewed native adapters exist. VNC also requires an explicit opt-in enforced by both the parent and helper before text reaches the RFB engine. Remote content is never copied to the Mac clipboard automatically.

The setting is deliberately visible in Quick Connect and saved profiles. The current macOS tests prove the safe rejection path without touching the host clipboard or any remote machine, including a loopback assertion that no RFB ClientCutText message is sent without opt-in. At runtime, the native helper also reports its actual capabilities, including transport encryption status, so the UI can keep unsupported or unsafe actions visible.
07 / local receipt

Recovery is tested
as a state machine.

The opt-in macOS RDP fixture runs the compiled helper against a real loopback IronRDP server, authenticates a synthetic username/domain/password, sends a real 400×240 monitor-layout request to the server display handler, closes the first server-side session, and verifies Reconnecting, a fresh Starting → Ready → Active sequence, and a different framebuffer from the second session. This proves one controlled engine/server pairing only; Windows, independent-server reconnect behavior, Gateway interoperability, and production packaging remain open.

VNC / local receipt

Protocol coverage
is explicit.

The isolated VNC helper now exercises real RFB 3.3, 3.7, and 3.8 negotiation on disposable loopback fixtures, including no-auth, legacy VNC-password, and categorized authentication-rejection paths. The same native client path is tested for framebuffer delivery and bounded input, without echoing the supplied secret in helper events. This is local engine evidence; TLS-capable engine selection, independent-server interoperability, and Windows/Linux/macOS release checks remain open.

PTY / local receipt

Shell targets stay
typed and bounded.

The macOS test suite launches each installed fixed Unix target—bash, zsh, and fish—inside a disposable native PTY and verifies a marker before clean exit. Windows PowerShell/cmd, WSL, Linux window-manager behavior, and the broader platform matrix still require their target environments.
