# MobaRust v0.1.29 — Stop Retries After Uncertain SSH Startup

**Free, open-source MobaXterm alternative built with Rust**

This release is in preparation. The published Mac previews remain v0.1.28;
Windows/Linux downloads remain v0.1.12. No v0.1.29 installer is published yet.

## What changed

- **Stop automatic retries after uncertain startup delivery:** if startup input
  times out or fails after the shell has opened, reconnect stops at that attempt.
  Some input may already have reached the server, so the error asks you to check
  the remote session and startup settings before reconnecting.
- **Keep ordinary connection recovery:** failures before startup input retain
  bounded retries. Success and explicit cancellation retain their existing paths.
- **Keep diagnostics private:** displayed startup errors include no configured
  commands, credentials or raw server text. The underlying failure stays typed.

Startup commands can still run again after a later approved reconnect. This
change does not guarantee exactly-once execution across connection loss.

## Evidence before release preparation

The source fix passed the local workspace checks. SDK fixtures cover startup
timeouts, partial input followed by peer closure and output overflow. Desktop
reconnect policy checks cover those typed failures and a transport failure;
they stop on the first uncertain attempt, including after an earlier retryable
connection failure.

A fresh macOS ARM64 debug app passed the native reconnect-timeout check against
a disposable loopback fixture: the first connection received its approved
startup input exactly once, a private fixture marker interrupted that transport,
and the replacement connection timed out with zero startup credit. The app
displayed the actionable error and made no third connection during a further
53.68 seconds with the fixture listener still available. Normal menu Quit
released the owned app and local PTY; the fixture deadline removed its private
metadata and released the loopback port.

[Source and native checks](../testing/ssh-reconnect.md#native-reconnect-startup-retry-stop--2026-10-03)
and [reproducible fixture instructions](../testing/ssh-lab.md#repeatable-native-reconnect-startup-lab-on-main)
describe the scope and limitations.

## Verified locally before installer builds

The version-aligned `cargo xtask check` passed on macOS ARM64, including
workspace tests/Clippy, frontend tests/type checks/lint/build, release/lab
tooling, isolated RDP/VNC fixtures, package-layout contracts and fuzz
compilation. It includes 109 desktop tests, 43 SSH unit tests, 16 authentication
cases and 25 OpenSSH cases. Four manual SSH labs remain opt-in; real Xvfb
reported its missing-prerequisite skip.

The refreshed RustSec database at `ef6173cbc5c50ec8166f9a5b28f07834144373ee`
(1,290 advisories) reports no vulnerabilities in the shipping workspace, VNC
helper or fuzz lockfile. The workspace retains proc-macro-error/glib warnings;
the excluded RDP candidate still fails on `RUSTSEC-2023-0071` and retains two
unmaintained warnings. No findings were suppressed. Only 15 local package
version entries changed across the four lockfiles; third-party packages did
not change.

## Release gates still pending

Both Mac installer builds, mounted package/signature/architecture checks,
ARM64 release-copy native
reconnect acceptance, checksum manifests and anonymous public download
verification must pass before publication. Intel GUI/hardware acceptance and
Windows/Linux alignment remain separate open gates.

These remain ad hoc signed Mac previews without Developer ID or notarization.
VNC/RDP remain experimental; RDP is absent from normal installers. The walkthrough
remains the real v0.1.17 recording. GitHub workflows remain disabled; historical
tags and releases are preserved.
