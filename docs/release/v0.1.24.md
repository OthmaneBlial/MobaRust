# MobaRust v0.1.24 — Reliable SFTP Reads & Writes

**Free, open-source MobaXterm alternative built with Rust.**

This Mac preview improves SFTP read cancellation, request cleanup and upload chunk sizing. Windows/Linux previews remain v0.1.12.

## What changed

- 📂 **Preserve unread file data.** A cancelled read resumed into a smaller buffer keeps the remaining bytes instead of overflowing that buffer or losing data. Positions advance by delivered bytes; seek, accepted write and handle closure retire old read state.
- 🔄 **Keep late replies from breaking the session.** Dropped async requests, queued write acknowledgments and file-drop closes release their local reply slots. A valid ordinary reply after timeout/cancellation is discarded without closing unrelated requests. Initialization errors and malformed frames still fail closed.
- ⬆️ **Split uploads to fit negotiated limits.** Read/write data limits cannot replace the packet budget. Upload chunks account for the handle and packet prefix, while 64-bit server limits are clamped before narrowing. Nonempty writes with no data room or a closed handle fail explicitly without advancing position.
- 🧪 **Retain focused regressions.** Five private SDK tests and 16 public in-memory boundary cases cover byte order, offsets, cancellation, late replies, negotiated limits and refusal paths. No app dependency version or feature changed.

## Validation and limits

All four published files were downloaded anonymously over HTTPS with HTTP 200 responses and compared byte for byte with the verified local files. Both downloaded SHA-256 manifests passed.

Both locally built DMGs passed `hdiutil verify`, read-only mounted layout checks and strict ad hoc signature verification. App/helper architectures match arm64/x86_64, both packaged CLI paths return `MobaRust 0.1.24` with disposable HOME and no SSH agent, and bundled LICENSE/NOTICE bytes match the repository. Inventory checks found no private lab/portable state or environment metadata. Both manifests passed and all owned mounts were detached.

Installers were built locally, offline, from source/tag `85965f56798f1771586108b8bca6730a9146883b`. The version-aligned source passed the complete local `cargo xtask check`: workspace tests/Clippy, frontend tests/type checking/lint/build, release/lab tooling, isolated RDP/VNC fixtures, package-layout contracts and fuzz compilation. Coverage includes 105 desktop tests, 42 SSH unit tests, 15 automated authentication cases, five private SDK checks, 16 in-memory SFTP boundary cases and all 16 OpenSSH cases. Three manual labs remain ignored; real Xvfb reports its missing-prerequisite skip.

The first release-preparation check hit existing X11 and frequent-rekey fixture deadlines. A test worker-budget experiment also failed and was removed. A test-owned xauth sample showed Rosetta startup; this Mac's Intel-only xauth was replaced on PATH by a native ARM64 client tool. The full recheck then passed with original scheduling, payload assertions and deadlines. This is runner-environment evidence, not an X11 runtime correction or proof of repeatable timing on every host.

SSH fixtures use loopback-only listeners, disposable state and generated credentials; focused SFTP peers use memory pipes only. Package/CLI checks do not establish native GUI startup, editor save/exit acceptance, sustained responsiveness, clean install/uninstall or Windows/Linux runtime behavior. Intel CLI checks use Rosetta on Apple Silicon, not Intel hardware. Cancellation cannot undo remote operations already transmitted; transfer Retry still restarts the transfer.

Mac previews have ad hoc signatures without Developer ID signing or notarization. Checksums establish byte integrity, not publisher identity. VNC/RDP remain experimental; the RDP candidate remains excluded from normal installers because of its known dependency advisory. The refreshed RustSec scan reports no workspace vulnerability while existing GTK/glib and unmaintained warnings remain. GitHub workflows remain disabled.
