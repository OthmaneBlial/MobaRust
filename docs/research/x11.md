# X11 forwarding research boundary

MobaRust does not claim to ship an integrated X server in the local terminal
slice. SSH X11 forwarding and an X server are two different capabilities:
SSH can carry the channel, but a local X display must still exist and accept
the forwarded connection.

## Architecture options

### External-server integration

The first realistic cross-platform option is to let the user install and
configure a trusted X server, then pass an explicit display target through the
native SSH transport. MobaRust can provide a setup check, a safe display
selector, and actionable diagnostics without bundling the server.

This keeps the distribution small and avoids making MobaRust responsible for
the X server's authentication, extensions, window lifecycle, and update chain.
It does not provide a MobaXterm-equivalent integrated display by itself.

### Bundled X server

A bundled server could provide a more integrated experience, but it creates a
separate native component with its own license, CVE response, sandboxing,
socket policy, display authentication, and packaging obligations. It must be
kept out of the main UI process and versioned independently. The Windows
distribution would need a tested server binary and an explicit firewall and
startup policy; silent background listening is not acceptable.

### Native display/socket helper

A helper process could own X server startup and expose only a narrow lifecycle
and display-status IPC contract. This contains crashes and makes cancellation
possible, but it does not remove the need for a vetted X server implementation
or solve platform-specific display integration. It is an architecture seam,
not an implementation shortcut.

## Platform behavior

### Windows

Windows has no native X display. An external X server such as a user-approved
X11 distribution is required, or MobaRust must ship a separately reviewed
server. The UI should verify that the selected display endpoint is reachable,
avoid changing firewall rules automatically, and explain whether the server
uses local display authentication. WSL GUI support is a separate path and
must not be conflated with SSH X11 forwarding.

### Linux

On X11 desktops, `$DISPLAY` and the Xauthority boundary are normally supplied
by the desktop session. On Wayland, Xwayland may provide compatibility, but
availability and policy vary by desktop environment. MobaRust should detect
the environment and report capability rather than assuming that `DISPLAY` is
usable. It must not copy or expose Xauthority cookies to React.

### macOS

macOS generally requires an external XQuartz installation for X11 display
support. MobaRust should detect the approved display endpoint and provide
setup diagnostics. It should not assume that a terminal's `-X` option implies
that XQuartz is installed or running.

## Security and dependencies

X11 clients can request broad access to a display, and forwarded X11 traffic
should be treated as sensitive remote interaction. Use trusted-host policy for
SSH, keep X11 forwarding opt-in, and show the remote host and local display
before connecting. Never expose `DISPLAY`, Xauthority cookies, or raw socket
credentials to the React layer or logs.

An integrated server would add native dependencies, platform binaries,
license notices, symbol/update management, and a larger attack surface. Any
candidate must pass license review, dependency audit, protocol interoperability
checks, and crash/cancellation tests before packaging.

## Release rule

The SSH protocol adapter may expose forwarding only after the display target
and security implications are explicit. Integrated X11 is a separate research
and packaging project, not a consequence of accepting an SSH `-X` setting.
If an integrated server is not feasible initially, provide excellent external
server detection and setup guidance rather than a fake implementation.
